# Travel Agent 工作台 UI·UX 优化设计文档

- 日期：2026-08-27
- 范围：桌面端（≥1180px）、Web 平板区间（900–1180px）、移动端（<900px，含 393×852 主验收视口）、微信/支付宝小程序
- 方法：基于 codex 会话 `019ff53b` 的全部历史调整记录、`design-qa.md`、7 份历史 audit、`DESIGN.md` / `PRODUCT.md`，按 impeccable skill 的 product register 与 adapt 流程产出
- 性质：**保留式优化（preserve-mode）**。信息架构、Chat/Trip/Map 三入口、对话主入口、确认边界、地图主导决策、品牌色全部不动；只优化交互流畅度、版面组织与平台适配

## 1. 背景与依据

### 1.1 历史收敛（codex 会话 019ff53b 摘要）

产品方向经过四轮收敛，已确定的、本文档不再推翻的结论：

1. **对话是唯一主入口**（2026-08-13 纠错）：用户绝不手工建行程；行程面板是 Agent 结果与待确认调整的工作台。
2. **地图驱动的旅行工作台**（2026-08-17 定稿）：桌面「对话 + 行程骨架 + 地图」同屏；移动端 Chat / Trip / Map 三入口。
3. **V2 工作台原则**（2026-08-20）：已确认路线始终留在主工作台；新候选只以提示条 + 候选池出现，不覆盖、不暗改原方案。
4. **核心交互闭环**（2026-08-26 最新一轮）：整趟安排概览 → 选一个环节 → 看替代方案 → 地图实时预览多点路线影响 → 试选不落盘 → 用户确认后才写入 TripState。
5. **视觉方向**：Quiet Map Canvas（`exec-9f581ce0` 为已确认桌面视觉基准）；移动端 map-pulse 路线详情方向。明亮中性底、珊瑚红单强调色、真实图片、克制留白。
6. **技术形态**：一套 React Web Core + PWA + Capacitor + 轻量原生小程序；不引入新 UI 框架与动效库。

### 1.3 优化目标

1. 让「看候选 → 试排 → 看影响 → 确认」闭环在三端都是**两步以内可达、影响一屏可读**。
2. 桌面端把地图从「右栏的一个模块」恢复为「工作台的底层画布」（TREK 调研结论的既定方向）。
3. 移动端修复结构性裁切，触控目标全部 ≥44px，信息按 adapt 原则重排而非缩放。
4. 样式系统收敛：三组断点、语义 z-index、4px 间距网格，为后续维护降本。

## 2. 设计 Token 规范（全端统一）

以下 token 以 `styles.css:1 :root` 现有值为准做**收敛与补全**，不改品牌色与既有语义色。

### 2.1 颜色

| Token | 值 | 用途 |
|---|---|---|
| `--ink` | `#17191c` | 主文字、决定性控件 |
| `--ink-soft` | `#38434b` | 次级文字、卡片副标题 |
| `--muted` | `#53616b` | 辅助说明（正文对比度 6.38:1，已实测过 AA） |
| `--quiet` | `#64727b` | placeholder、最弱提示（5.26:1） |
| `--line` | `#dfe4e7` | 分隔线 |
| `--line-strong` | `#cbd3d8` | 强调分隔、输入框默认边 |
| `--canvas` | `#f6f8f9` | 页面底 |
| `--surface` | `#ffffff` | 卡片、面板 |
| `--surface-subtle` | `#f0f4f5` | 侧栏/工具条第二层中性面 |
| `--coral` | `#ff5a4f` | 品牌、地点标记、候选更新提示（不作文字按钮底色） |
| `--coral-action` | `#c9443b` | 主按钮底色（白字 4.80:1，AA） |
| `--coral-deep` | `#b93630` | 主按钮 hover/active |
| `--coral-soft` | `#fff0ed` | 试排中/候选提示的软底 |
| `--blue` | `#2166bd` | 路线推荐、链接、focus ring |
| `--blue-soft` | `#edf4fb` | 路线步骤软底 |
| `--green` | `#24754b` | 已核验/已确认/体力校验通过 |
| `--green-soft` | `#e8f6ec` | 通过态软底 |
| `--amber` | `#84531d` | 准备项、Provider/新鲜度限制、试排警告 |
| `--amber-soft` | `#fff7ef` | 警告软底 |

规则（沿用 DESIGN.md 并强化）：

- 颜色策略为 **Restrained**：珊瑚色只出现在主操作、当前选择、试排/候选状态与地图标记，占比 ≤10%。
- 状态永远不只靠颜色：已确认=绿徽章+「已确认」文字；试排中=珊瑚徽章+「试排中」文字；限制=琥珀徽章+图标+文字。
- 禁用：渐变文字、玻璃拟态、AI 紫、装饰性地图纹理、彩色侧条纹（side-stripe border）。
- 灰色文字不上彩色底；彩色软底上的文字用同色相深色（如 `--amber` on `--amber-soft`）。

### 2.2 字体与字阶

单一系统栈，不下载网络字体：

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Noto Sans CJK SC", sans-serif;
```

固定 rem 字阶（product register：不用 fluid clamp 做标题），比例约 1.2：

| 层级 | 规格 | 用途 |
|---|---|---|
| Display | 32px / 750 / -0.02em | 空状态主标题、桌面工作台大标题（仅一处/屏） |
| H1 | 24px / 700 | 面板标题（整趟安排、环节比较） |
| H2 | 20px / 650–700 | 卡片组标题、抽屉标题 |
| H3 | 17px / 650 | 环节卡名称、候选卡名称 |
| Body | 15px / 400–500 | 正文、对话消息 |
| Small | 13px / 400–500 | 辅助说明、元信息 |
| Micro | 11–12px / 500 | 徽章、来源新鲜度、证据标注（**不低于 11px**，DESIGN.md 硬性约束） |

- 中文文案：短事实分句 + 一句明确状态或下一步；路线标题与设施状态永不截断，辅助细节可截断。
- 正文行长 ≤65–75ch；对话气泡 max-width 约 68ch。
- 移动端正文 ≥14px，输入框文字 16px（防 iOS 聚焦自动放大）。

### 2.3 间距与圆角

- 间距网格：4px 基数，常用 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48。卡片内边距 16（移动 14）；面板内边距 20–24；区段间距 24–32。
- 圆角：`--radius-control: 10px`（输入、按钮）、`--radius-card: 14px`（卡片、sheet，上限 16px）、状态胶囊/标签可用 full pill。**卡片不超过 16px，杜绝 24px+ 过度圆角**。
- 触控目标：移动端与 `pointer: coarse` 下 ≥44×44px；桌面主操作 ≥36px，输入框 40–48px。

### 2.4 层级与阴影

层级来自留白、1px 分隔线与表面切换，不靠阴影堆叠：

- 平面元素：只有 1px `--line` 边框，**无**装饰性投影（禁止 border + 宽软阴影同时出现）。
- 浮层（drawer、sheet、登录弹层、toast）：唯一允许阴影的层级，`0 8px 24px rgba(23,25,28,0.12)`（blur ≤24，不用 ≥16 blur 配 1px border 的 ghost-card 组合）。
- 语义 z-index（替换任意值）：

```css
--z-sticky: 10;        /* 面板内 sticky 摘要条 */
--z-topbar: 20;        /* 顶栏 / 移动底部 tab */
--z-backdrop: 30;      /* 抽屉遮罩 */
--z-drawer: 40;        /* history drawer、候选池、登录弹层 */
--z-sheet: 50;         /* 移动 bottom sheet、详情 */
--z-toast: 60;
--z-tooltip: 70;
```

### 2.5 断点（收敛为三组 + 两组容器查询）

| 断点 | 行为 |
|---|---|
| <560px | 紧凑手机：字号微调、统计四格改 2×2、composer 图标化 |
| <900px | 移动结构：单列 + 底部三入口 tab；工作区整页切换 |
| 900–1180px | 平板/窄桌面：对话栏覆盖式 drawer（非常驻），工作区双列（决策列 + 地图） |
| ≥1180px | 桌面结构：对话栏常驻可调宽 + 决策列 + 地图三区域 |

- 废弃 1120 / 1220 / 760 / 420 零散断点；工作区内部「决策列 + 地图」的堆叠改用**容器查询**（容器 <860px 时地图置顶、决策列在下），与视口解耦。
- 横屏手机（高度 <500px）：底部 tab 改为左侧窄轨 56px，地图区保留。

### 2.6 动效

| 场景 | 参数 |
|---|---|
| 面板/视图切换 | 200ms，`cubic-bezier(0.22, 1, 0.36, 1)`（ease-out-quint 近似），transform + opacity |
| 候选卡 hover/选中 | 120–150ms ease-out，仅 border/背景色 |
| 试排路线绘制 | polyline 300ms 描画 + 影响条数字 250ms 计数过渡 |
| Bottom sheet / drawer | 250ms，transform-only，带 backdrop 200ms 淡入 |
| 骨架屏 | opacity 呼吸 1.2s，不用位移 |
| 页面加载 | **无编排式入场动画**（product register：产品加载即进入任务） |

- 全部动画在 `@media (prefers-reduced-motion: reduce)` 下降级为 100ms 交叉淡入或即时切换。
- 不动画 layout 属性（width/height/top/left）；面板调宽拖拽期间禁动画。

## 3. 桌面端 / Web 端设计（≥1180px 主工作态）

### 3.1 版面总览

```
┌──────────────────────────────────────────────────────────────────┐
│ Topbar 56px                                                       │
├───────────────┬───────────────────┬──────────────────────────────┤
│ 对话栏         │ 决策列             │ 地图区（底层画布）             │
│ 320–440px     │ 400–480px         │ flex-1（min 420px）           │
│ 可拖拽/折叠    │ 整趟安排⇄环节比较   │ 地图 + 影响条 + 站点面板       │
└───────────────┴───────────────────┴──────────────────────────────┘
```

- **Topbar 56px**（现 68px，降高释放纵向空间）：左起「☰ 我的行程」（打开 history drawer）→ 品牌标 → 旅行摘要胶囊「上海 · 8/27–29 · 3 人」（可点击，打开行程信息编辑）→ 弹性空间 → 语言切换 → 账户/登录。存在试排时，旅行摘要右侧出现一个**珊瑚软底胶囊「试排中 · 未确认」**，点击直达试排环节。
- **对话栏**：默认 380px，拖柄 6px（hover 加粗、`ArrowLeft/Right` 键盘步进 16px），范围 320–440px；折叠为 48px 窄条只留展开按钮。内含 ConversationPanel：消息流 + ThinkingMessage + ActivityStrip + quick replies + Composer。
- **决策列**：默认 440px，有两个互斥视图：**整趟安排**（默认）与**环节比较**（选中环节后）。不弹 modal，视图内切换，保留空间上下文。
- **地图区**：地图即画布，常驻；其上是浮动工具（专注地图、定位），其下是**路线影响条**（试排时出现）与**可折叠的按时间看每一站**（默认收起）。

### 3.2 整趟安排视图（决策列默认态）

自上而下：

1. **视图头**：H1「整趟安排」+ 副标题「先看整趟，再进入一个环节比较替代方案」；右侧「出发前还差 N 项」琥珀摘要条（点击展开 ReadinessPanel，执行「我已准备 / 需要帮助 / 官方入口」）。
2. **旅行级 chips 行**：预算 ¥8,000 · 天气 小雨 3 天 · 同行 3 人（含长辈步行 ≤600m）。每个 chip 可点击：预算→对话预填；天气→WeatherPlanningCard 展开；同行→TravelerCareSummary。
3. **环节列表**（按时间序，连续行式卡片，非嵌套卡片）：每个环节一行卡片，结构：

```
┌─────────────────────────────────────────┐
│ [域图标] 环节类型            [状态徽章]  │
│ 名称（17px/650，永不截断）               │
│ 第 1 天 18:00–19:30 · 建议              │
│ ¥564 起 · 评分 4.5 · 另有 2 个替代  ›   │
└─────────────────────────────────────────┘
```

   - 域图标：抵达 `AirplaneLanding`、住宿 `Bed`、餐饮 `ForkKnife`、游玩 `MapPin`、交通 `Train`，20px，`--ink-soft`，圆形浅底（不再使用大图缩略图做列表行，图片留给详情与候选卡）。
   - 状态徽章右对齐：已确认=绿软底「已确认」；试排中=珊瑚软底「试排中」；待研究=灰「待研究」；有风险=琥珀软底「需备选」。
   - 末行是**取舍摘要**：价格/评分/与锚点距离 + 「另有 N 个替代」+ chevron，整行是点击目标（≥56px 行高），不再是 11px 纯文字（修 P0-2）。
   - 试排中的环节整卡加 1.5px `--coral` 边框（无侧条纹），与徽章双重编码。

4. **底部固定条**（sticky bottom）：「整趟预算使用 ¥564 / ¥8,000 · 已确认 2/4 项」，右侧次级按钮「查看完整行程单」（只读汇总，可打印）。

### 3.3 环节比较视图（选中环节后）

进入方式：点击环节卡。决策列原地切换（200ms 横向滑移），布局：

1. **面包屑**：「‹ 整趟安排 / 住宿锚点」（返回按钮 44px 触控区，修 P1-3）。
2. **环节上下文条**：该环节的时间窗、约束（「决定每天往返距离和休息质量」）、当前状态。
3. **当前方案卡**（置顶，标注绿色「当前 · 已确认」）：图片 72×72 圆角 8px、名称、价格/评分、关键取舍 chips（「离外滩步行 12 分钟」「大床房 · 1 份早餐」「限时取消」）、来源与新鲜度「已核验 · 8/26 21:30」、次级按钮「图片、地图与详情 ›」（打开 PlaceDetailSheet）。
4. **候选卡列表**（最多 3–5 张，按推荐序）：与当前方案卡同构，额外一个**主按钮「试排」**（次强调样式：白底、`--coral-action` 文字与边框）。
   - 卡片差异高亮：与当前方案相比的关键差异 chips 前置（「+¥120 · 离地铁更近 300m」）。
   - 不可比项诚实标注：「含早未知」「取消政策待核验」，不隐藏。
5. **底部说明**：来源列表与「这些候选不会改动行程，确认后才写入」。

### 3.4 试排态（核心闭环，修 P0-3）

点击候选卡「试排」后，三区域同时进入试排态：

- **决策列**：该候选卡标记珊瑚徽章「试排中」，其余候选保持可选（可连点切换试排对象，200ms 内重算）。
- **地图区**：
  - 已确认当前路线以**低饱和灰蓝实线**保留可见（基准对照，不消失）；
  - 试排路线以 `--blue` 实线（weight 5）绘制，300ms 描画动画；对照方案灰色虚线；
  - 多点标记：机场→酒店→游玩→餐饮→酒店 编号 divIcon，试排涉及的点用珊瑚色描边强调；
  - 地图下方出现**路线影响条**（sticky，48px，蓝软底）：

```
试排影响  Δ +86 分钟 · Δ +1,102 m 步行 · Δ +¥88 ｜ 体力校验 581/600 m · 换乘 1/1 ✓
```

    Δ 值相对当前已确认方案，正增益琥珀、负增益绿色、中性灰；体力校验通过绿色、超限琥珀并给出一句解释（「超出父亲步行上限 102m」）。
- **确认栏**（sticky bottom of 地图区，56px，白底上阴影分隔）：左「保持当前」（次级，放弃试排）｜ 右「采用此方案」（主按钮 `--coral-action`）。**影响条与确认栏相邻同屏**，用户在 10cm 视距内完成「看影响 → 决策」（修 P0-3 的空间分离）。
- **不落盘承诺**：确认栏下方 11px 灰字「试排不会修改已确认行程」。点击「采用此方案」→ TripPatchProposal 走既有 revision/read set/write contract 提交流程 → 成功 toast「已更新住宿锚点，路线已重算」→ 退出试排态。

### 3.5 地图区细节

- 地图占满区域（flex-1），圆角 14px、1px `--line` 边框；开发底图 OSM，页脚 11px 常驻「OpenStreetMap 开发底图 · 正式导航以高德为准」。
- 浮动控件：右上「专注地图」切换（隐藏决策列，地图横扩；再按恢复）；右下缩放 ±（44px）；左上试排时显示「对比：当前 vs 试排」图例。Web 与桌面端在精细指针设备上支持鼠标滚轮或触控板缩放；移动端支持双指捏合缩放并保留单指拖动，不用双指手势替代可见的 ± 控件。
- **按时间看每一站**面板：默认**收起为一条 40px 摘要条**（「5 段移动 · 138 分钟 · 步行 1,102 m · ¥240 ▴」），点击展开为站点时间线（修 P1-1）。展开态每站一行：编号、到达/离开时间、地点、交通方式 chips（打车 7 分钟 / 公交 20 分钟 · 步行 521m），试排站点珊瑚标注。展开不改变地图尺寸（面板叠加在地图下缘，max-height 45%，内部滚动）。
- 空态（行程未建立）：地图区显示「地图和行程会在这里出现」+ 三步说明（先看空间关系 / 只比较关键取舍 / 确认后才加入旅行），**移除大幅营销感 hero 图**（修 P2-2），改为同构骨架轮廓（浅灰地图网格 + 虚线路线占位），与提交后的骨架屏视觉连续。

### 3.6 对话栏细节

- 消息气泡：用户=墨底白字（现状保持），Agent=白底 1px 边框；时间戳 11px `--quiet`。
- Agent 消息内的可执行建议以**内联快捷回复 chips**（「少走路」「位置优先」「控制预算」）呈现，点击即发送，不是装饰。
- 「展开完整说明」折叠长消息（现状已有，保留）。
- Composer：可见 label「说说这趟旅行」、占位示例轮换、Enter 发送 / Shift+Enter 换行提示；附件（图片 ≤3MB JPEG/PNG/WebP、链接、语音）按钮 40px；语音先转文字经确认再发送；敏感信息提示常驻 11px。
- 生成反馈：提交后决策列与地图区立即进入**同构骨架屏**（骨架形状与最终环节卡/地图一致），不停留在静态介绍（design-qa 既有结论，保留）。

### 3.7 桌面空状态（首趟）

- 对话栏：H1「从一句话开始规划」+ 三张 starter 卡（带家人轻松旅行 / 第一次探索一座城 / 先控制整趟预算）+ 附件提示，保持现状（已验收）。
- 工作区：按 3.5 的空态地图 + 决策列骨架轮廓，暗示即将出现的内容结构。
- 移动端空态见 §4.4。

### 3.8 Web 端专属（浏览器/键盘）

- 快捷键：`⌘/Ctrl + K` 聚焦 Composer；`⌘/Ctrl + B` 折叠对话栏；`Esc` 关闭 drawer/sheet/退出试排（二次确认不拦截）；决策列内 `↑/↓` 移动环节焦点、`Enter` 进入比较。
- 焦点：3px `--blue` 半透明 outline，所有交互元素可达；试排确认栏打开时焦点落入「采用此方案」。
- 刷新恢复：会话经 API 恢复（现状已有）；试排态不落盘、刷新即丢弃，属预期且文案说明。
- 900–1180px 区间：对话栏转为覆盖式 drawer（顶栏汉堡触发），工作区保持「决策列 + 地图」双列；<860px 容器宽度时地图置顶、决策列置下（容器查询）。

## 4. 移动端设计（<900px，主验收 393×852）

### 4.1 版面总览（修 P0-1）

```
┌─────────────────────────┐
│ Topbar 48px  品牌+摘要   │
├─────────────────────────┤
│                         │
│   当前 tab 视图          │
│   （对话 / 行程 / 地图） │
│                         │
├─────────────────────────┤
│ Tab bar 56px + 安全区    │
│  对话 · 行程ⁿ · 地图     │
└─────────────────────────┘
```

- **三入口从顶栏内嵌移到独立底部 tab bar**（thumb-first，根除裁切）：对话 `ChatCircle`、行程 `ListChecks`（带未决策计数 badge）、地图 `MapTrifold`。激活 tab 用 `--coral-action` 图标+文字，未激活 `--muted`。tab bar 56px + `env(safe-area-inset-bottom)`，白底、顶部 1px `--line`。
- Topbar 48px：品牌标 + 旅行摘要一行（「上海 · 8/27–29 · 3 人」），右侧「我的行程」图标按钮；不再塞 tab。
- 视图切换用 React 状态（现状 `mobileView` 机制保留），未激活面板 `display:none` 而非视觉隐藏，避免地图在后台持续布局。

### 4.2 对话 tab

- 消息流占满；Composer sticky 底部（在 tab bar 之上）：输入框 min-height 48px、文字 16px；附件/语音/发送按钮 44px（design-qa 已验收 42–44px，统一为 44）。
- 快捷回复 chips 横滑（隐藏滚动条，保留触控滚动）。
- 键盘弹出时 Composer 随键盘上浮，tab bar 隐藏（`visualViewport` 监听），避免双重占位。

### 4.3 行程 tab

首屏顺序（design-qa 已定，微调）：

1. 「出发前还差 N 项」摘要条（琥珀，可展开）。
2. **整趟安排环节列表**（同桌面 §3.2 的行式卡片，行高 ≥64px，整行可点）。
3. 行程摘要尾条（预算/已确认计数）。
4. 不再内嵌大地图：列表中每个环节卡的「地图定位」按钮与顶部「查看地图」入口跳到**地图 tab**（自动聚焦该点）。

点选环节 → **全屏环节比较页**（非 drawer，移动端 drawer 层级太深）：顶部返回栏 48px「‹ 整趟安排」，内容同桌面 §3.3（当前方案卡 + 候选卡），候选卡主按钮「试排」点击后**自动切到地图 tab** 并进入试排态。

### 4.4 地图 tab 与试排态

- 地图占视口上部 45–55%；下方是**路线 sheet**（bottom sheet，snap 45% / 85%，拖拽柄常驻）：
  - 收起态：影响条（试排时）或路线摘要（「5 段移动 · 138 分钟 · 1,102 m · ¥240」）。
  - 半展开：按时间看每一站（每站一行，交通 chips）。
  - 全展开：站点详情、设施（无障碍电梯/卫生间/寄存柜/充电宝，跟随当前步骤出现，不铺清单）。
- 试排确认栏 sticky 于 sheet 收起态下缘（tab bar 之上）：「保持当前」｜「采用此方案」，与影响条相邻（同桌面 §3.4）。
- 详情（PlaceDetailSheet）保持贴底 sheet；候选池在移动端不再是独立 drawer，而是环节比较页内的列表（与桌面 IA 一致，修一致性）。
- 空状态：starters 之后以**骨架轮廓卡**填充（「行程草案会在这里出现」占位），消除下半屏死区（修 P2-1）；或把首张 starter 之后的区域让给一条「示例旅行」横向卡片条。二选一，实现时取骨架方案（信息更诚实）。

### 4.5 移动端通用

- 触控目标全部 ≥44×44px；列表行间分隔用 1px 线而非卡片间距（省纵向空间）。
- 图片懒加载 + `srcset`；底图瓦片按视口加载。
- `viewport-fit=cover` + 四向 `env(safe-area-inset-*)`；横屏（高 <500px）时 tab bar 转左侧 56px 窄轨。
- `@media (hover: none)` 下无 hover 依赖；长按候选卡出现「试排 / 详情」快捷菜单（可选增强）。

## 5. 小程序差异（微信 / 支付宝）

- 沿用单页三 tab 结构，但 tab 迁移到**底部自定义 tabBar**（与 Web 移动版一致）；原生 tabBar 会限制样式，用自定义组件以保留 badge 与珊瑚强调。
- 地图用原生 `<map>` 组件；路线 sheet 用 movable-view 实现 45/85% snap。
- Composer 无语音入口（平台限制维持现状），图片上传走平台 API；所有请求打已登记 HTTPS API。
- 登录只交换平台一次性 code；授权失败显示「待开放」而非假成功。
- 字号/触控目标与 §4 一致；iOS 小程序安全区由平台处理，底部 tab 预留 34px home indicator 区。

## 6. 状态系统（加载 / 空 / 错误 / 降级）

| 状态 | 表现 |
|---|---|
| 加载 | 同构骨架屏（决策列环节卡骨架 + 地图网格骨架），opacity 呼吸 1.2s；不用居中 spinner |
| 空（无行程） | §3.7 / §4.4 空态，说明「地图和行程会在这里出现」+ 骨架轮廓 |
| Provider 不可用 | 对应域环节卡显示琥珀「待研究 · 来源暂不可用」，附原因与下一步；不伪造候选 |
| 路线重算中 | 影响条骨架 200ms 内出现，数值区显示「重算中…」；确认栏禁用 |
| 提交失败 | toast + 确认栏错误条「未写入，行程保持原样 · 重试」；试排态保留 |
| 地图降级 | Leaflet → 高德静态图 → 「地图待补」占位，三级均有文字说明（现状保留） |
|  freshness | 每张候选卡标注「已核验 · 时间」；过期转琥珀「信息可能过时」 |

## 7. 问题 → 方案映射与验收

| 问题 | 方案 | 验收方式 |
|---|---|---|
| P0-1 移动 tab 裁切 | 底部 tab bar（§4.1） | 393×852 截图三 tab 完整可见、触控 44px |
| P0-2 替代入口弱 | 环节卡末行取舍摘要 + 整行点击 + 环节比较视图（§3.2/3.3） | 任意环节 1 次点击看到全部候选 |
| P0-3 影响与确认分离 | 地图下影响条 + 相邻 sticky 确认栏（§3.4/4.4） | 试排态单屏内可读影响并确认 |
| P1-1 右栏过载 | 站点面板默认收起、地图为画布（§3.5） | 1440×900 下地图可视高 ≥55% |
| P1-2 环节卡不可扫描 | 行式卡片信息分层（§3.2） | 3 秒内读出状态/价格/替代数 |
| P1-3 无环节导航 | 面包屑 + Esc 返回（§3.3） | 键盘可完整走通比较流程 |
| P1-4 断点失控 | 三断点 + 容器查询 + z-index 收敛（§2.5/2.4） | `styles.css` 断点仅剩 560/900/1180 |
| P2-1 移动空态死区 | 骨架轮廓填充（§4.4） | 393×852 空态无 >120px 空白 |
| P2-2 桌面空态营销感 | 同构骨架替代 hero 图（§3.5） | 空态与提交后骨架视觉连续 |
| P2-3 键盘路径不明 | 快捷键与焦点规范（§3.8） | 键盘完成「比较→试排→确认」 |

**实现顺序建议**：P0（tab bar、环节卡、试排影响条/确认栏）→ P1（站点面板收起、面包屑、断点收敛）→ P2（空态、快捷键）。每步完成后按 `design-qa.md` 既有流程做 1280/1440/393 三视口截图验收 + `npm run check`。

**沿用 P3 遗留**：Windows 125%/150% 缩放、宽折叠屏、Capacitor 与小程序真机、生产高德底图，按 design-qa.md 原样保留为后续里程碑。
