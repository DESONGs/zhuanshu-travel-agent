# Travel Evidence Companion 产品需求文档

> 版本：PRD v0.2
>
> 状态：产品方向已确认；地图与 Plan–Check–Repair 已具备承接能力，下一阶段按“无账号证据闭环 → Electron 安全 Spike → 桌面证据阅读器 → 隔离自动发现”推进。
>
> 本文是功能级 PRD，不替代 `wiki/current/01-product.md`，不构成当前开发线程的执行指令。
>
> 技术证据与采用边界见 [Evidence Companion 下一阶段技术调研](./2026-08-31-evidence-companion-next-iteration-technical-research.md)。

## 1. 产品结论

Travel Agent 的核心价值是：

> 帮用户从中国本地内容、地图和 OTA 中发现值得去的地方，用用户能理解的语言呈现原始图文证据，再把选择转化成可执行的地图路线。

用户感知到的完整体验应当是：

```text
说出想法
→ 看见候选
→ 看懂当地人的真实体验
→ 比较是否适合自己
→ 放进地图试排
→ 看见时间、预算和体力变化
→ 确认行程
→ 在官方渠道完成购买
```

小红书、抖音、微信、地图、OTA 和到访反馈都是证据来源，不是独立产品栏目。产品不复制小红书 Feed，也不把用户送进一堆互不关联的外部页面。

## 2. 用户问题

### 2.1 入境自由行者

- 知道中国本地内容更丰富，但看不懂中文；
- 难以判断帖子中的地点、菜品、入口、排队和支付信息；
- 不知道内容是否适合自己的同行人、时间和住宿位置；
- 在社交内容、地图和 OTA 之间反复切换后，仍然无法得到可执行路线；
- 不一定拥有小红书账号，也不应在体验产品前被要求注册。

### 2.2 国内旅行者

- 能看懂小红书，但不想阅读大量雷同攻略；
- 需要区分真实到访、软广、同源转载和商家自述；
- 希望快速知道哪家店或哪个体验更适合当前行程；
- 选择地点后，需要立刻看见动线、预算和时间变化。

### 2.3 家庭与小团体

- 同行人的步行、楼梯、饮食、语言和节奏要求不同；
- 图片中的门面、座位、菜单、房间和实际环境会影响选择；
- 推荐理由必须能绑定到具体 Traveler，而不是泛泛地说“适合家庭”。

## 3. 用户任务

### 3.1 核心 Job to Be Done

当我看到一个陌生的餐厅、酒店、景点或路线时，我希望快速看到可靠的图文证据，并知道它放入当前旅行是否合适，从而不必自己在多个中文平台之间搬运和重排信息。

### 3.2 辅助任务

- 打开某条原帖或 OTA 详情；
- 阅读翻译摘要、逐段译文和图片文字；
- 判断来源是否独立、近期或存在商业倾向；
- 核对地图、营业、价格、房态、班次和设施；
- 试排候选并比较路线影响；
- 在官方渠道完成登录、实名和交易；
- 返回 Travel Agent 后记录已经完成的外部动作。

## 4. 产品原则

1. **证据服务于当前决定。** 每条内容必须回答当前候选为什么值得看、是否适合、仍缺什么。
2. **图像承担判断作用。** 门面、环境、菜品、菜单、入口、房间和拥挤程度不能被装饰图替代。
3. **原文、翻译、Agent 推断分层。** 用户能追溯原始来源，机器翻译和适配分析不能伪装成作者原话。
4. **先试排，再确认。** 社交发现进入现有 Mobility Preview 和 TripPatchProposal，用户确认前不改变 TripState。
5. **不强制社交登录。** 没有小红书账号时仍可使用已取得的公开、运营、合作或 Worker 证据。
6. **交易回到官方渠道。** 阅读和比较可以留在产品内，实名、支付、投保、购票和退改必须外部完成。
7. **失败不能阻断整趟旅行。** 社交来源不可用时保留地图、OTA、官方资料和明确缺口。

## 5. 产品信息架构

Evidence Companion 不是第四个常驻栏目，而是现有 Chat / Decision / Map 工作台中的临时专注模式。

### 5.1 规划模式

```text
┌────────────┬────────────────┬────────────────────┐
│ 旅行对话   │ 当前决策       │ 地图与路线         │
│            │                │                    │
│ 用户要求   │ 抵达           │ 当前 Day 多点路线  │
│ Agent 解释 │ 住宿           │ 路段、方式与影响   │
│            │ 餐饮           │                    │
│            │ 游玩           │                    │
└────────────┴────────────────┴────────────────────┘
```

候选在默认状态只显示一条可理解的内容判断：

```text
野森季·云南菜

[主图] 当地特色 · 适合轻松晚餐
       人均约 ¥120 · 距酒店约 18 分钟

当地人怎么说
“菌子锅适合多人，但节假日排队较久”
来自 4 条到访内容，2 条可能同源

[看图文证据] [试排进路线]
```

候选卡不直接铺开帖子列表，不以来源数量冒充可信度。

### 5.2 证据模式

桌面端点击“看图文证据”后，进入同一窗口的 Evidence Companion：

```text
┌────────────┬──────────────────────────┬─────────────────┐
│ 对话可折叠 │ 原始图文证据             │ 旅行判断伴随栏  │
│            │                          │                 │
│ 当前需求   │ 大图、图集或原始页面     │ 为什么值得去    │
│ 候选关系   │ 中文正文与评论           │ 是否适合同行人  │
│            │                          │ 排队与预约      │
│            │                          │ 路线与预算影响  │
│            │                          │ 来源差异        │
│            │                          │ [试排进路线]    │
└────────────┴──────────────────────────┴─────────────────┘
```

- ≥ 1440px：保留窄对话栏、媒体阅读区和判断伴随栏；
- 1180–1439px：对话栏折叠，原始证据约占 60%，伴随栏约占 40%；
- < 1180px：证据阅读成为全屏页，底部固定“试排进路线”；
- 关闭后恢复原候选、滚动位置和地图焦点。

### 5.3 试排模式

点击“试排进路线”后，原始来源收敛为来源条，地图重新成为主画布：

```text
野森季已加入试排

路线变化
酒店 → 餐厅：约 18 分钟
餐厅 → 外滩：约 32 分钟

整趟影响
+ ¥360 餐饮估算
+ 50 分钟
父亲最长连续步行 420 米，未超过 600 米
返回酒店时间由 20:40 调整至 21:30

[采用这次调整] [返回证据] [比较另一家]
```

地图、时间轴、预算、步行、换乘和同行人影响必须来自现有服务端核验。社交内容不能生成路线事实。

### 5.4 外部履约模式

OTA 的房型、班次、价格和规则可以在 Evidence Companion 中阅读和翻译。以下动作统一跳转官方网页或 App：

- 账号登录；
- 实名乘客和证件；
- 支付、保险和最终下单；
- 退票、改签、取消和退款。

外部完成后，用户回到 Travel Agent 手动记录确认，不自动读取支付和证件资料。

## 6. 图文证据体验

### 6.1 媒体首屏

```text
┌─────────────────────────────────────┐
│ 1 / 6                   查看原帖 ↗  │
│                                     │
│           当前证据大图              │
│                                     │
├─────────────────────────────────────┤
│ [门面] [菜品] [环境] [菜单] [排队] │
├─────────────────────────────────────┤
│ 快速看懂 · English                  │
│ 这是一家位于……的云南菜餐厅。       │
│ 多位近期到访者提到……               │
└─────────────────────────────────────┘
```

无真实图片时显示来源缺口，不使用通用风景图替代地点。

### 6.2 翻译层级

| 模式 | 默认行为 | 适用场景 |
| --- | --- | --- |
| 快速看懂 | 提炼特色、价格、排队、预约、入口、风险和适配结论 | 大多数用户快速判断 |
| 逐段对照 | 原文、译文和“对这趟旅行的影响”分栏 | 需要理解上下文和语气 |
| 翻译图片 | 用户主动选择当前图片或区域，识别菜单、标牌和截图文字 | 图像承载主要信息 |

产品语言初步按中文、英语、西班牙语、法语、阿拉伯语、俄语、日语和韩语规划；后两种语言在实施前按入境客源验证。阿拉伯语必须支持 RTL。

### 6.3 Claim 聚合

同一判断不按帖子平铺：

```text
排队情况
3 条独立来源提到高峰期等待 30–60 分钟
1 条内容与其中一篇图片和文案高度相似

[查看 3 条来源]
```

聚合维度包括：

- 地方特色与推荐菜；
- 排队、预约和营业变化；
- 价格和份量；
- 交通、入口和实际步行环境；
- 季节、天气和拥挤程度；
- 语言、支付、点单和过敏原；
- 争议、同源转载和商业倾向。

## 7. 内容获取策略

### 7.1 三层来源

| 层级 | 来源 | 账号要求 | 产品角色 |
| --- | --- | --- | --- |
| 无账号基础层 | 用户分享链接、公开页面、运营与创作者授权资料 | 产品方不需要账号 | 稳定基础能力 |
| 用户侧阅读层 | Electron 隔离阅读会话 | 用户可能自行登录 | 桌面深度阅读与翻译 |
| 产品增强层 | 一个或少量专用账号的隔离只读 Worker | 产品方专用账号 | Agent 有界自动发现 |

多个账号不能用于绕过平台风控、挑战或限流。长期稳定覆盖需要内容合作或授权资料库。

### 7.2 无账号用户

外国游客默认先看到已取得的翻译摘要、来源数量和核验状态。只有打开受限原帖时才提示登录：

```text
这篇原帖需要小红书登录

你仍可查看 Agent 已整理的旅行摘要。
登录只用于在这台设备阅读原帖，Travel Agent 不读取密码。

[扫码登录小红书] [继续看摘要]
```

登录失败不能清空当前候选或行程。

## 8. 跨端职责

| 平台 | Evidence Companion 能力 |
| --- | --- |
| Electron 桌面端 | 原始网页、用户本机会话、图文翻译、来源比较、路线试排和官方跳转 |
| Web / PWA | 归一化图文证据、翻译摘要、授权缩略图、外部原帖链接；第三方禁止嵌入时诚实降级 |
| Capacitor | 移动证据摘要、用户主动图片翻译、地图试排和官方 App 跳转 |
| 微信 / 支付宝小程序 | 紧凑“当地人怎么说”、翻译摘要、打开平台和轻量 Trial，不复制桌面阅读器 |

全平台共享候选、Claim、Trip revision 和 Proposal 结果，不要求共享同一页面结构。

## 9. 状态与错误

| 状态 | 用户界面 |
| --- | --- |
| 正在取得内容 | 显示真实来源活动，不预演“正在分析帖子” |
| 公开内容已读取 | 展示图文、来源和 checkedAt |
| 需要用户登录 | 提供扫码登录和继续看摘要两个动作 |
| Worker 需要登录 | 不要求普通用户处理，降级其他来源 |
| Challenge / Rate limit | 停止自动化，保留已有证据并说明影响 |
| 原始页面变化 | 标记来源已变化，允许重新读取或打开原页 |
| 翻译失败 | 保留原文和图片，不生成模型猜测 |
| 图片不可授权展示 | 在原始页面查看，候选卡使用其他合法图片 |
| 地点未归一 | 允许阅读证据，但禁止试排和确认 |
| 路线核验失败 | 保留候选，禁止采用 Trial |

工程错误码、Schema 和 Provider 名称不直接暴露给普通用户。

## 10. 当前迭代范围

### 10.1 纳入

- 当前候选中的“当地人怎么说”；
- 图文 Evidence Companion；
- 快速看懂、逐段翻译和用户主动图片翻译；
- 用户分享链接解析；
- Electron 受限原页阅读方案；
- OTA 原始资料核验和官方履约跳转；
- 社交 Claim 到现有路线 Trial 的闭环；
- 来源独立性、商业倾向、时间和缺口展示；
- 一个专用账号 Worker 的设计与安全门，不默认声明已接线。

### 10.2 暂不纳入

- 小红书 Feed、关注、点赞、收藏、评论、私信或发布；
- 通用浏览器、任意 URL、扩展系统、下载器或密码管理器；
- 多账号轮换和风控绕过；
- 自动支付、下单、退改或证件填写；
- 原网页逐字悬浮覆盖翻译；
- 大规模长期保存完整帖子和原始媒体；
- 未获授权的公开内容再分发。

## 11. 成功指标

### 11.1 核心指标

- 打开证据后完成“试排进路线”的比例；
- 证据 Trial 被用户最终确认的比例；
- 入境用户从中文证据到可理解决定的完成率；
- 用户在社交平台、地图和 OTA 之间的往返次数下降；
- 社交来源不可用时仍完成主方案的比例。

### 11.2 质量指标

- 原文、翻译和 Agent 推断错误混淆率；
- 地点实体归一成功率；
- 同源内容聚类准确率；
- 翻译失败和图片不可用恢复率；
- 未确认 Trial 修改 TripState 的次数必须为 0；
- Cookie、Token、证件和支付资料进入日志或 Prompt 的次数必须为 0。

候选数量、帖子数量和页面停留不能单独代表成功。

## 12. 验收场景

### 12.1 入境游客发现本地餐厅

英语用户询问上海本帮菜小店。系统返回至少一个真实餐厅候选，展示地图或官方图片、多个来源 Claim 和英文快速摘要。用户进入 Evidence Companion 查看门面、菜品和排队证据，试排后看到与酒店、外滩、预算和父亲步行限制的变化。确认前 Trip revision 不变。

### 12.2 无小红书账号

用户没有小红书账号，仍能查看已取得的英文证据摘要和合法图片。打开受限原帖时可选择扫码登录或继续看摘要，不被阻断。

### 12.3 用户本机登录

Electron 使用隔离 Session 打开小红书登录页。登录成功后原帖在同一窗口显示；Travel Agent 不读取 Cookie、密码和账号资料。关闭 Evidence Companion 后行程状态不变。

### 12.4 图片翻译

用户主动选择菜单图。系统只处理选择区域，返回原文、译文和可能的过敏原提示；无法确认的文字标为不确定，不生成价格或菜名。

### 12.5 OTA 核验

用户在 Evidence Companion 查看酒店房型、早餐、退改和价格来源；点击预订后打开官方渠道。返回产品后由用户记录确认，不自动读取订单或支付资料。

### 12.6 Worker 风控

专用账号遇到 Challenge 后立即停止。本轮仍展示高德、OTA、用户链接和已有社交证据，明确“本次未取得新的当地内容”，不伪装为空结果。

## 13. 实施前置门

主线程地图和跨端能力已完成开发验证，但相关工作区修改尚未形成新的 Git baseline。下一阶段开始前必须：

1. 先提交并标记地图/跨端成果，形成可回滚 baseline；
2. 复用当前 `RouteMapScene`、`TripMapExplorer`、地点详情和 Mobility Trial，不重写地图；
3. Evidence Companion 进入现有 Candidate Detail / Map Workspace，不建立第二套全屏详情系统；
4. 先完成无需社交账号的 Web 闭环，再决定 Electron 是否通过 Spike；
5. Social Worker 只有在固定版本审计、平台条款审查和真实隔离 smoke 通过后才能排期；
6. 将实际进入开发的增量同步到当前产品文档与决策记录。

## 14. 已收敛与待复核决策

已收敛：

- 现有 React/Vite Web Core 保留，Electron 只作为增强桌面壳；
- Evidence Presentation 是可丢弃读模型，不成为第二份 TripState 或 Evidence Graph；
- Electron 使用可信 App View 与不可信 Evidence View 分离，不采用 `<webview>`；
- 首发不依赖小红书官方公共搜索 API，因为当前官方能力不支持该用途；
- 用户分享链接和已取得证据先行，自动搜索 Worker 后置；
- 社交候选最终必须进入现有多点路线 Trial，而不是停留在帖子阅读；
- 实名、支付、购票和退改始终交给官方渠道。

仍待复核：

- 入境八语中日语、韩语是否按市场数据保留；
- Electron Spike 中本地自定义协议与 AMap JS 的真实兼容性；
- 高德和 OTA 图片的展示授权范围；
- 小红书专用账号 Worker 的平台条款和书面授权；
- 创作者授权资料进入产品的许可合同；
- 翻译缓存的保存期限与删除机制；
- Evidence Companion 首发建议优先吃、玩，同时让住、行复用同一读模型；最终范围按 E1 真实数据覆盖决定。
