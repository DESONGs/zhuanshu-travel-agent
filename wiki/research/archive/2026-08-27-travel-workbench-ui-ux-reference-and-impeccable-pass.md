# Travel Workbench UI/UX 参考与 Impeccable 优化记录

> 日期：2026-08-27
> 范围：只优化现有 Web Core 的旅行规划体验，不改变 Parent Agent、TripState、Evidence、Proposal、Provider、HTTP/MCP 或购买确认边界。

## 参考结论

### TREK

[TREK](https://github.com/liketrek/TREK) 的旅行页采用稳定地图、按天计划区和未规划地点池；地点支持跨日移动，地图提供分类筛选和路线可视化。适合本产品采用的是：

- 地图在规划时保持空间上下文，不因切换候选消失；
- 日程骨架与候选池是不同状态；
- 天气与日期直接绑定；
- 桌面端允许高密度规划，移动端使用专门布局。

没有采用其费用、文件、列表、协作、预订等多页签导航。Travel Agent 当前的价值时刻是“从自然语言得到可比较、可执行的路线”，引入完整旅行管理后台会增加认知负担并重复已有能力。

### Airbnb Trips

[Airbnb 2025 Summer Release](https://news.airbnb.com/product-releases/airbnb-2025-summer-release/) 的 Trips 视图把住宿、入住、体验与时间节点组织为一条内容优先时间轴。适合本产品采用的是：

- 当前安排先用图片、时间和一个明确动作表达；
- 详细规则、来源和设施按需展开；
- 预订内容与发现内容在视觉状态上区分。

没有采用其交易优先底部导航和大型营销图片比例，因为本产品仍需同时表达路线影响、证据缺口与同行人约束。

### 其他旅行规划产品

[Product Hunt Travel Planning](https://www.producthunt.com/categories/travel-planning) 中 Mindtrip、Copilot2trip、MapMagic 等产品共同强调互动地图、可编辑行程和预订衔接。采用“地图和选择共享焦点”，不采用一次性 AI 生成后无法继续编辑的结果页。

## 本轮产品判断

原“行、住、玩、吃四段候选纵向展开”虽然信息完整，但造成三个问题：

1. 页面很长，用户先看到候选墙，难以快速读出当前整趟安排；
2. 地图在常见 1440px 桌面、对话展开时可能被压到下一屏；
3. 已确认状态仍显示永久底部确认条，制造无效主操作。

新的信息结构是：

`整趟安排概览 → 选择一个环节 → 查看当前项与替代项 → 地图预览影响 → 有变更时才确认`

## 已实施

- 行程概览固定显示抵达、住宿、餐饮、游玩四个当前选择，包含图片、时间、确认/试排状态和替代数量。
- 点击一个环节后自动滚动到该领域的候选轨道；其他领域保持在概览中，不继续纵向铺满全部候选。
- 地图在大于约 900px 的工作区容器中保持右侧同屏；1440px 桌面对话展开时仍为双栏。
- 活跃候选使用内容更充足的图片卡；确认态和试排态使用完整边框/底色，不使用侧边色条或宽模糊阴影。
- 天气压缩为始终可见的摘要，展开后才显示每日预报和四域影响。
- 预算与同行人体力合并为路线下方两项摘要；修复“¥$600”货币文案错误。
- 没有试选时不再显示禁用的主确认条；发生试选时才出现“确认替换/加入路线”。
- 试选状态收回 Planning Workbench 内部管理；取消试选会使在途预览失效，不会在稍后用陈旧结果覆盖已确认路线。
- 默认桌面对话宽度由 420px 收紧为 380px，仍可拖动并可折叠。

## 真实 UI 验收

- 1855px：对话、整趟安排、当前候选和地图均可读，地图占据稳定右侧区域。
- 1440×900：工作区约 943px，保持 `430px + 495px` 双栏；无页面级横向溢出，地图在第一屏可见。
- 390×844：Chat / Trip / Map 三入口保持；Trip 概览为单列，点击餐饮后焦点区自动进入视口；`scrollWidth === clientWidth === 390`。
- 候选详情、领域切换、试选、取消试选、地图存在性均通过真实浏览器操作。

## 保留边界

- 地图、路线、库存、价格和天气仍只展示具名来源返回的数据；视觉优化不能制造缺失事实。
- 移动端完整地图继续由 Map/Today 入口承担，Trip 不复制桌面大地图编辑器。
- 当前不增加拖拽排序。只有在 Day Timeline 合同能够表达跨日调整与影响预览后，才引入 TREK 式拖动。
- TREK 为 AGPL 项目，只参考公开产品结构，不复制代码或受限素材。

## 失败恢复与会话管理补充

真实 Computer Use 演示发现并修复三类问题：

- 切换候选时，新 Mobility Preview 最多等待 45 秒；请求切换或取消时会中止旧请求。新路线成功前保留上一版完整地图和指标，失败后显示“重新核验路线”，并禁用确认。
- 酒店等 OTA 节点自身可能没有坐标，但已在 Mobility 路线端点中解析。详情页现在按 `nodeId` 复用该坐标，只显示当前地点；切换地点时抽屉回到顶部，不再截断首图。
- “我的行程”升级为“旅行与对话”管理，提供进行中、最近删除、新建、删除确认和恢复。删除只软删除 Conversation，关联 TripState 与已确认选择保留。
